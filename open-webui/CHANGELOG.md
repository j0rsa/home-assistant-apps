# Changelog

## 0.12.4

- Update upstream from `v0.12.3` to `v0.12.4` ([compare](https://github.com/open-webui/open-webui/compare/v0.12.3...v0.12.4))
- Upstream v0.12.4 ([notes](https://github.com/open-webui/open-webui/releases/tag/v0.12.4))
- 🎯 **Load selected skills on demand.** Administrators can turn on "Load selected skills on demand" under Admin Settings > General or set "ENABLE_SKILL_LAZY_LOADING", so skills selected in the chat or attached to a model are only listed for the model to load when it needs them instead of sending their full instructions with every message, while skills mentioned in the message still load right away, and it is off by default and needs the built-in Skills tool.
- 📍 **Compaction shown in chats.** A "Context compacted" line now marks the message where older messages were summarized, opens to show the summary and also appears inside a reply when compaction ran between its tool calls, Chat Controls > Overview tags that message, and compaction progress and errors now show in the chat instead of as pop-up notices. [#31324](https://github.com/open-webui/open-webui/issues/31324)
- 🗜️ **Compaction in more chats.** Context compaction now also runs in temporary chats and in short chats that are already over the threshold, such as one question with a reply full of tool output, so the follow-up and any regenerate or edit of it no longer fail with a context length error. [#32794](https://github.com/open-webui/open-webui/pull/32794), [#32781](https://github.com/open-webui/open-webui/issues/32781), [#32600](https://github.com/open-webui/open-webui/issues/32600)
- 🕶️ **Hide controls for users.** Administrators can now hide single controls from users under Visible controls in Admin Settings > Interface or with "UI_VISIBILITY", such as model capabilities, default features and built-in tools in the model editor, Capture, Compare text, Attach Webpage, Attach Files, Attach Notes, Attach Knowledge and Reference Chats in the + menu, the /status, /model and /settings commands, the usage info, Fork, Merge Responses, Preview, Artifacts, Archive and Tags in chats, Set as default and Keep in Sidebar for models and settings such as the Usage tab and the speech engines, while hidden controls keep their values and the features behind them stay usable, hiding Archive also hides Unarchive, and administrators still see every control. [#32830](https://github.com/open-webui/open-webui/issues/32830)
- 🫙 **Unavailable options hidden.** Options that cannot take effect are now hidden, such as Capture in the + menu without a Vision model, Attach Notes for users without the Notes permission, the Valves pickers in Chat Controls for disabled tools and functions, the Context Compaction Threshold while context compaction is off, the title, follow-up and tag generation switches in Settings > Interface while the admin has turned them off, Compress Images in Channels for users who cannot use channels, the Web Search in Chat setting while web search is not available to the user, the Voice section of Settings > Interface for users who cannot make calls, group and default permission toggles for features the admin has turned off, the Terminal capability and default terminal in the model editor while no terminal server or direct integration is available, the New Temporary Chat and Delete Chat shortcuts for users who may not use them, the Web Search, Image Generation, Code Interpreter and Memory capabilities and Default Features in the model editor while that feature is off for the instance, built-in tools in the model editor that the model's capabilities rule out or whose feature is off, the engine settings in Admin Settings > Web Search and Admin Settings > Images while web search or image generation is off, the Web Search Query Generation switch in Admin Settings > Interface while web search is off, the Regenerate Menu and terminal settings in Settings > Interface while they cannot apply, "/skills:create" for models that cannot create skills, the Call button while speech-to-text is unavailable, the Audio settings tab for users allowed no speech or calls, the multi-factor authentication section while MFA does not apply to the user and the openwebui.com author link on a new chat while community sharing is off, while saved values are kept for when they apply again. [#32969](https://github.com/open-webui/open-webui/pull/32969), [#32967](https://github.com/open-webui/open-webui/pull/32967), [#32959](https://github.com/open-webui/open-webui/pull/32959), [#32962](https://github.com/open-webui/open-webui/pull/32962), [#32973](https://github.com/open-webui/open-webui/pull/32973), [#32976](https://github.com/open-webui/open-webui/pull/32976), [#32977](https://github.com/open-webui/open-webui/pull/32977), [#32980](https://github.com/open-webui/open-webui/pull/32980), [#32961](https://github.com/open-webui/open-webui/pull/32961), [#32972](https://github.com/open-webui/open-webui/pull/32972), [#32975](https://github.com/open-webui/open-webui/pull/32975), [#32983](https://github.com/open-webui/open-webui/pull/32983), [#32966](https://github.com/open-webui/open-webui/pull/32966), [#32978](https://github.com/open-webui/open-webui/pull/32978), [#32963](https://github.com/open-webui/open-webui/pull/32963), [#32965](https://github.com/open-webui/open-webui/pull/32965), [#32984](https://github.com/open-webui/open-webui/pull/32984), [#32985](https://github.com/open-webui/open-webui/pull/32985), [#32986](https://github.com/open-webui/open-webui/pull/32986), [#32974](https://github.com/open-webui/open-webui/pull/32974), [#32981](https://github.com/open-webui/open-webui/pull/32981), [#32971](https://github.com/open-webui/open-webui/pull/32971), [#32970](https://github.com/open-webui/open-webui/pull/32970), [#32964](https://github.com/open-webui/open-webui/pull/32964), [#32830](https://github.com/open-webui/open-webui/issues/32830)
- 🔏 **Access button respects sharing.** The Access button and menu entry of models, prompts, tools, knowledge, skills and notes and the Access button in folder settings are now hidden from users without the matching sharing permission, who had nothing they could change in its dialog. [#32979](https://github.com/open-webui/open-webui/pull/32979), [#32830](https://github.com/open-webui/open-webui/issues/32830)
- 🖇️ **Attach entries without uploads.** When files cannot be attached, because of a missing permission or a selected model without File Upload, the greyed Attach Knowledge, Reference Chats and Attach Notes entries in the + menu no longer open and the # and @ lists leave out what cannot be attached, including pasted links for users without the web upload permission, so a picked item no longer vanishes from the input without a message. [#32968](https://github.com/open-webui/open-webui/pull/32968), [#32830](https://github.com/open-webui/open-webui/issues/32830)
- ⏱️ **Exact last active time.** Hovering the last active time in the admin user list and in a group's member list now shows the exact date and time.
- 🗨️ **New chat from folders.** A folder's menu in the sidebar now has a New Chat item that starts a chat in that folder.
- 🪪 **Profile cards across the workspace.** Hovering an owner's name in the workspace lists of models, knowledge, prompts, skills and tools and in admin Functions now opens their profile card instead of an email tooltip, with their profile picture next to the name, profile pictures in access settings, version history and the Analytics user list open the card too and the Notes list shows each owner's profile picture.
- 🔢 **Turn count in chat previews.** The preview shown when hovering a chat in the sidebar now shows how many user and assistant turns its current branch has.
- 🎚️ **Chat Controls saved per setting.** A change in a chat's Controls, such as its system prompt or a parameter, now saves only that setting, so a copy of the chat open in another tab or on another device no longer wipes it with older settings. [#32755](https://github.com/open-webui/open-webui/issues/32755)
- 🪃 **Questions survive reconnects.** When the page reloads or loses its connection while Ask User, a tool approval, an MCP server's input request or a function's confirmation or input dialog waits for you, the question now comes back once you reopen that chat within a minute, so the request no longer waits without an answer.
- ✍️ **Note edits by text.** The model can now edit a note by finding and replacing exact text instead of only by character offsets, picking one match or all of them and getting the positions and surrounding text back when a match is ambiguous. [#32752](https://github.com/open-webui/open-webui/issues/32752)
- 🔍 **Compare view stays aligned.** Matching rows in the two panes of the Compare view now stay lined up and in place while scrolling, resizing or editing, and a colored bar now marks changed lines also while whitespace or emphasis markers are ignored.
- 🖱️ **Clickable setting labels.** Clicking the label of a setting across user and admin settings, including advanced parameters and connections, now toggles its switch, focuses its field or presses its button, and the label highlights while the row is hovered or focused, so the right control is easier to find. [#32768](https://github.com/open-webui/open-webui/issues/32768), [#32900](https://github.com/open-webui/open-webui/issues/32900)
- ☑️ **Select several sidebar chats.** Shift-clicking a chat in the sidebar starts a selection that more clicks or a shift-click range extend, and the selected chats can then be archived or, with the delete permission, deleted together, while Escape clears the selection. [#32543](https://github.com/open-webui/open-webui/issues/32543)
- 🫲 **Swipe open Chat Controls.** On a phone, swiping left across a chat now pulls in the Chat Controls panel, which follows your finger like the sidebar does and closes again with a swipe to the right.
- 🗃️ **Bulk file management.** Manage Files in Settings > Data Controls can now download a single file and lets you select several files or all files matching a search to delete them or download them together as one zip archive, with progress and a stop button.
- 📥 **Accurate upload status.** A file uploaded to a knowledge base now only shows as done once it is indexed and linked to the knowledge base, so it no longer shows as done and then goes missing from the list until a reload. [#32803](https://github.com/open-webui/open-webui/issues/32803)
- ⏳ **Knowledge files show Processing.** A file added to a knowledge base now switches from Uploading to Processing once it reaches the server, and the list keeps itself up to date until the file is ready, so it no longer says Uploading until you reopen the knowledge base. [#32982](https://github.com/open-webui/open-webui/pull/32982)
- 🧮 **Knowledge uploads listed at once.** Files selected or dropped together into a knowledge base now all appear as Uploading right away in upload order, so each one no longer waits to appear until the file before it has finished processing. [#32992](https://github.com/open-webui/open-webui/pull/32992)
- 📈 **Analytics by tokens.** The Admin Analytics dashboard now ranks models and users by tokens by default with a switch back to messages, and its usage chart adds volume and activity views, a single model view, a comparison with the previous period, a choice of time steps and Year to date and Last 12 months ranges.
- 🗂️ **File browser grid view.** The terminal file browser can now switch between a list and a grid view from its menu, folders show how many items they hold, and on larger screens hovering a file shows a preview, up to 1 MB for text files and 20 MB for images, audio, video and documents.
- 📁 **File browser folder menu.** A folder's menu in the terminal file browser now has New File and New Folder items that create the file or folder inside that folder.
- 📬 **First-message terminal uploads.** With Chat Uploads set to Filesystem on a Per chat terminal, a file attached to the first message of a new chat now waits and uploads into that chat's own terminal when the message is sent, so it no longer lands in the shared workspace. [#30245](https://github.com/open-webui/open-webui/issues/30245)
- 🪧 **Folder descriptions.** Folders can now have a description in their settings, shown under the folder title on the folder's page.
- 🚚 **Organize chats in shared folders.** The owner of a shared folder can now rename chats other people started in it and drag them to another folder within the same shared folder.
- 🛰️ **MCP protocol 2026-07-28.** MCP connections now also work with servers that speak the stateless 2026-07-28 protocol version, while older servers still connect through the earlier handshake. [#33087](https://github.com/open-webui/open-webui/pull/33087), [#29778](https://github.com/open-webui/open-webui/issues/29778)
- 📧 **LDAP default email domain.** Administrators can now set a default email domain in the LDAP settings or with "LDAP_DEFAULT_EMAIL_DOMAIN", so LDAP users without a mail attribute sign in with their username at that domain as their email address and into any existing account with that address, which is why the domain should be one you control. [#33001](https://github.com/open-webui/open-webui/issues/33001)
- 🔐 **OAuth connections over the API.** Connections set to OAuth authentication now also send the user's OAuth token when the user calls the API with an API key or bearer token, like tool servers already did. [#32826](https://github.com/open-webui/open-webui/pull/32826), [#32820](https://github.com/open-webui/open-webui/issues/32820)
- 🫣 **Hidden base models for groups.** Administrators can now turn on the Hidden Models permission under Models Access in the user and group permissions, or set "USER_PERMISSIONS_WORKSPACE_MODELS_HIDDEN", so those users can pick hidden models as the base model of a workspace model while the hidden models stay out of their model picker. [#29806](https://github.com/open-webui/open-webui/discussions/29806), [#29639](https://github.com/open-webui/open-webui/issues/29639)
- 🧾 **Model usage in audit logs.** With audit logging on and "/chat" removed from "AUDIT_EXCLUDED_PATHS", where it is excluded by default, each chat reply and tool call round now writes its own audit log entry with the model and the input, output and total tokens the provider reported, linked to the request that started it. [#30098](https://github.com/open-webui/open-webui/issues/30098)
- 📨 **Voice call user headers.** With "ENABLE_FORWARD_USER_INFO_HEADERS" on, Realtime voice calls now also send the user info headers, or the signed user JWT when configured, to the realtime provider, like chat requests do. [#32733](https://github.com/open-webui/open-webui/pull/32733)
- 🏎️ **Faster action buttons.** An action button now only saves the chat again when the action changed a message, so actions on large chats finish sooner. [#32658](https://github.com/open-webui/open-webui/issues/32658)
- 👪 **Faster group saves.** Saving, deleting or changing the members or permissions of a group now finishes in well under a second with thousands of users online, where it took several seconds and reloaded the open chat of everyone online. [#32883](https://github.com/open-webui/open-webui/pull/32883), [#32882](https://github.com/open-webui/open-webui/pull/32882)
- 🧳 **Faster folder changes.** Renaming, sharing, moving or deleting a folder and deleting all chats now finish quickly with thousands of users online, where each took several seconds and reloaded the open chat of everyone online. [#32888](https://github.com/open-webui/open-webui/pull/32888)
- 📣 **Faster channel posts.** Posting a message in a channel with many members online now returns in a fraction of a second, where it waited for every online member's login to be checked again first. [#32889](https://github.com/open-webui/open-webui/pull/32889)
- 📊 **Faster analytics dashboard.** The Admin Analytics dashboard now gets its totals, model and user lists and daily charts from fewer and lighter database queries, so it opens faster on instances with many messages.
- ♻️ **Prompt cache survives restarts.** Tools from tool servers, Open Terminal included, now reach the model in the same form after every restart, so the provider's prompt cache keeps working and long chats are no longer processed again from scratch. [#33000](https://github.com/open-webui/open-webui/pull/33000)
- 👁️ **PDF image OCR stays light.** With PDF Extract Images (OCR) on, reading text from images in PDFs now uses one processor thread per upload by default, so uploads no longer start a thread pool the size of the server's cores that could slow the whole server down, and administrators can pass their own RapidOCR settings with "RAPIDOCR_PARAMS". [#32844](https://github.com/open-webui/open-webui/issues/32844)

- 📤 **Chat export permission respected.** The Export item of a folder in the sidebar, the Export option in Archived Chats and the Copy option in the chat menu are now hidden from users without the Allow Chat Export permission, like the export options of single chats. [#32703](https://github.com/open-webui/open-webui/pull/32703), [#32702](https://github.com/open-webui/open-webui/issues/32702), [#32684](https://github.com/open-webui/open-webui/pull/32684), [#32683](https://github.com/open-webui/open-webui/issues/32683), [#32960](https://github.com/open-webui/open-webui/pull/32960)
- 🎛️ **Pipe Valves permission respected.** The Valves button of a pipe model in the chat input is now hidden from users without the Allow Chat Valves permission. [#32772](https://github.com/open-webui/open-webui/pull/32772), [#32771](https://github.com/open-webui/open-webui/issues/32771)
- 👥 **One model without Multiple Models.** A new chat now starts with a single model for users without the Multiple Models permission, where a default or a link with several models kept them all selected. [#32668](https://github.com/open-webui/open-webui/pull/32668), [#32667](https://github.com/open-webui/open-webui/issues/32667)
- 🖊️ **Chat Edit permission respected.** The Edit button of a user's own messages is now hidden from users without the Allow Chat Edit permission, where only the Edit button of replies was hidden. [#32841](https://github.com/open-webui/open-webui/pull/32841), [#32832](https://github.com/open-webui/open-webui/issues/32832)
- 📅 **Calendar page respects access.** Opening the Calendar page with Calendar turned off or without the Calendar permission now returns to the home page, where it showed an empty calendar and an error. [#32837](https://github.com/open-webui/open-webui/pull/32837), [#32834](https://github.com/open-webui/open-webui/issues/32834)
- 🔒 **Live access after archiving.** People who see a chat through a shared folder now stop receiving its live updates when the owner archives it or archives all chats, and people with a share link stop when the owner unshares all chats, as they already did when a single chat was unshared or deleted. [#32887](https://github.com/open-webui/open-webui/pull/32887)
- 🧵 **Thread replies deleted too.** Deleting a channel message now also deletes its thread replies, which stayed behind and could still be found in search. [#32666](https://github.com/open-webui/open-webui/pull/32666), [#32665](https://github.com/open-webui/open-webui/issues/32665)
- 🔗 **Shared chat pages load once.** Chats opened under /s/, through a share link or by an administrator viewing another user's chat, no longer reload over and over and jump back to the bottom, which since 0.12.3 made scrolling up impossible. [#32725](https://github.com/open-webui/open-webui/pull/32725), [#32657](https://github.com/open-webui/open-webui/issues/32657)
- 🧹 **Deleting the open chat.** Deleting the chat you are viewing from the sidebar now opens an empty new chat, where the deleted chat's messages stayed on screen and the next message failed, in Safari with "The string did not match the expected pattern." [#33069](https://github.com/open-webui/open-webui/pull/33069), [#33068](https://github.com/open-webui/open-webui/issues/33068)
- 🪡 **More Concise and Add Details.** Choosing More Concise or Add Details or typing a suggestion under a reply now rewrites that reply, where the model got the instruction without the reply and answered it on its own, for example with "OK, I'll keep answers shorter". [#33084](https://github.com/open-webui/open-webui/pull/33084), [#33083](https://github.com/open-webui/open-webui/issues/33083)
- 📱 **Sign-in page on small screens.** The sign-in page can now be scrolled when it is taller than the screen, such as on phones with the keyboard open, where parts of the form could be out of reach.
- 🖼️ **Note menu image uploads.** Images picked with Upload files in a note's menu now appear in the note, where they were saved with the note's files but never inserted. [#32793](https://github.com/open-webui/open-webui/pull/32793), [#32792](https://github.com/open-webui/open-webui/issues/32792)
- 📜 **Prompt history on unchanged saves.** Saving a prompt without changes no longer adds an identical version to its history. [#32709](https://github.com/open-webui/open-webui/pull/32709), [#32708](https://github.com/open-webui/open-webui/issues/32708)
- 🎨 **Images after tool approval.** Images the model generates after you answer its question or approve or reject a tool call now appear in the reply, where they were created but never shown and the model kept retrying with more hidden images. [#32680](https://github.com/open-webui/open-webui/pull/32680), [#32678](https://github.com/open-webui/open-webui/issues/32678)
- 🧬 **Embeddings with Prefix ID.** The embeddings API now works with models from a connection that has a Prefix ID, where the provider rejected the prefixed model name as unknown. [#32724](https://github.com/open-webui/open-webui/pull/32724), [#32715](https://github.com/open-webui/open-webui/issues/32715)
- 📞 **Realtime calls answer once.** A Realtime call no longer answers the same sentence twice when a short pause splits it into two turns. [#32773](https://github.com/open-webui/open-webui/pull/32773), [#32764](https://github.com/open-webui/open-webui/issues/32764)
- ⬅️ **Right-to-left question cards.** Question cards from Ask User now follow the Chat Direction setting, so Hebrew and Arabic questions and answers are laid out right to left. [#32784](https://github.com/open-webui/open-webui/pull/32784), [#32778](https://github.com/open-webui/open-webui/issues/32778)
- 🛠️ **Same-named tool functions.** When two attached tools have a function with the same name, the model can now call both, where only the first one could be called. [#32670](https://github.com/open-webui/open-webui/pull/32670), [#32669](https://github.com/open-webui/open-webui/issues/32669)
- 🧷 **Tool server array parameters.** An array query parameter now reaches an OpenAPI tool server as repeated values instead of one text value that looks like a Python list. [#32677](https://github.com/open-webui/open-webui/pull/32677), [#32676](https://github.com/open-webui/open-webui/issues/32676)
- 📖 **Reading files in pages.** The model's file reading tools now return every part of a file or knowledge base file read in pages with line numbers on, where some text between pages was skipped, and asking for only an end line now reads from the first line up to it, where the model got the same opening part back and kept retrying. Opening the pane puts you in a tab, starting your shell where nothing else is running, and closing the last tab folds the pane away again.
- 📂 **Folder uploads to terminals.** The file browser beside a terminal takes a folder now, dropped onto it or picked from the Upload Folder entry in its menus, and rebuilds what is inside it as it goes, subfolders and all, where before a drop uploaded only the files sitting loose at the top.
- ⚖️ **Side-by-side file comparison.** Picking two files in the file browser lights up a Compare button that lays them side by side or one above the other, numbering the lines, marking what was added and removed down to the part of the line that changed, counting both, and letting you swap which is which or leave whitespace out of it, a choice it remembers; a terminal too old to offer the comparison says so rather than failing quietly.
- 🌐 **Suggested prompts in your language.** A fresh install now offers its suggested starter prompts in the language the interface is set to, rather than the same four in English for everyone, and the model defaults panel carries a way back to those defaults once its own suggestions have been edited.
- 📏 **Exa result length cap.** Web search through Exa can be held to a number of characters per result, set beside its key in the admin web search settings or as "EXA_MAX_CONTENT_LENGTH".
- 🇪🇺 **European web search option.** Staan can now be picked as the web search provider, giving deployments that need search inside the EU an option they do not have to host themselves, configured from the admin web search settings or through "STAAN_API_KEY", "STAAN_MARKET" and "STAAN_MAX_SNIPPETS". [#30138](https://github.com/open-webui/open-webui/pull/30138), [#26006](https://github.com/open-webui/open-webui/discussions/26006), [#30303](https://github.com/open-webui/open-webui/pull/30303), [#30301](https://github.com/open-webui/open-webui/issues/30301)
- 🗣️ **Per-language names and descriptions.** A model, tool, skill, function, banner or arena entry can now hold its name, description, starter prompts and valve labels once per language, written in a searchable table in its own editor or brought in as a JSON file, which is refused where a translation drops one of the placeholders the original fills in. The interface shows the wording for the language it is set to, and falls back to the plain text where that language has none.

- 🔓 **Turning off the sign-in form.** The box asking for an email address and a password can now be taken off the sign-in page from the authentication settings, where until now it could only be set before the server started, leaving single sign-on or a directory to sign people in.

[#29635](https://github.com/open-webui/open-webui/pull/29635), [#29633](https://github.com/open-webui/open-webui/issues/29633), [#29640](https://github.com/open-webui/open-webui/pull/29640), [#29637](https://github.com/open-webui/open-webui/issues/29637)

[#28185](https://github.com/open-webui/open-webui/pull/28185)

[#28184](https://github.com/open-webui/open-webui/pull/28184), [#28169](https://github.com/open-webui/open-webui/issues/28169)

- 🚪 **Signing out ends the session.** Signing out or having every token revoked left any live connection that account already had in place, and those are now cut at the same moment; a token already revoked can no longer be replayed to cut someone else's newer session.
- 🛡 **Diagrams and SVG stay on this origin.** Mermaid diagrams and SVG previews, attached or uploaded, no longer follow references pointing at another origin, a picture, style or configuration line among them, and a diagram that reaches outside is refused with an error; a file whose drawing leans on an external sprite now shows that part blank. [#30271](https://github.com/open-webui/open-webui/pull/30271)
- 📲 **Terminal sessions follow access changes.** A terminal connection now re-checks your access to it every ten seconds for as long as it stays open, so removing someone's permission or deactivating their account ends their live terminal on the next check, on every worker and not only the one they signed in through.
- 🔒 **Connection model listing access.** The endpoints that list the models on a single Ollama or OpenAI connection could be reached by a signed-in account of any role, and now check the caller's role. [#29619](https://github.com/open-webui/open-webui/pull/29619)
- 🔏 **Knowledge file access.** A file's access through a knowledge base now follows its actual attachment alone, rather than also a collection name left behind on the file record. [#29937](https://github.com/open-webui/open-webui/pull/29937)

[#29887](https://github.com/open-webui/open-webui/pull/29887)
- 🍪 **Cookie forwarding scope.** A connection authenticating as the signed-in person is handed this instance's browser cookies only where its new Forward cookies switch is on, which an instance relying on it has to turn on after upgrading.
- 🗝️ **Revocation list fallback.** Where the revocation list is kept in Redis and Redis cannot be reached, a token is now accepted rather than the request failing, so signing out may not take effect until Redis is back.
- 🗒 **Home page chat drafts.** A message typed into a chat started from the home page now comes back after a reload, text, uploads and all, where the draft was stored under a key the page never read again. [#29762](https://github.com/open-webui/open-webui/pull/29762), [#29760](https://github.com/open-webui/open-webui/issues/29760)

[#29623](https://github.com/open-webui/open-webui/pull/29623)

[#30070](https://github.com/open-webui/open-webui/pull/30070)
- 🗒️ **Note save on exit.** A note's title and its attachments save a moment after they change, and leaving the note inside that moment dropped the save, so the notes list kept showing the old title until the page was reloaded; the pending save now finishes before the next page opens. [#29745](https://github.com/open-webui/open-webui/pull/29745), [#29744](https://github.com/open-webui/open-webui/issues/29744)
- 📷 **Attachments sent without text.** Sending an image or a file with nothing typed to a model that has skills attached replaced the empty message with the list of skill names, so the model answered with its own catalogue instead of looking at what you sent. [#30045](https://github.com/open-webui/open-webui/pull/30045), [#30040](https://github.com/open-webui/open-webui/issues/30040)

[#30183](https://github.com/open-webui/open-webui/pull/30183)

- ♿ **Wider accessibility mode coverage.** Accessibility mode now lifts the contrast of more of the interface, including muted text, table text, icons, the colours elements change to on hover, and the highlight behind sidebar and menu items you point at, so low-contrast areas meet the level the accessibility guidelines ask for in both light and dark themes, and the close button on the folder dialog now announces itself to screen readers, as do document and slide previews, which can now be reached with the keyboard. - 📶 **Streaming rebuilt from the ground up.** A reply now streams as small pieces of new text instead of resending the whole message so far with every update, so the data sent over a reply grows with its length rather than with its length squared, which on a server with many people chatting at once means far less processor time spent encoding, passing, and decoding those updates, far less load and memory on the shared cache that carries them between instances, and far less work in your browser, which no longer takes in the whole reply again and redraws the parts of it that have not changed on every update, cutting the data sent and the server work spent appending to a message by up to 1000x on a very long reply, and a reply still in progress is now kept aside on the server, so reopening the conversation after a refresh picks it up where it is rather than showing a blank message, on deployments backed by Redis.
- 🪵 **Much faster throughout.** Hundreds of places across the application no longer assemble detailed log text that is switched off and thrown away unread, so sending messages, uploading and indexing files, running searches, signing in, and loading admin pages all get that time back, with the largest gains on busy servers, in long conversations, and on chats that draw from a large knowledge base. - 🔠 **Interface scaling throughout.** The UI Scale setting and your browser's own text size now resize the whole interface consistently, including the sidebar, menus, dialogs, and file browser, rather than leaving parts of it fixed.
- 🏷️ **Named writing blocks.** When a model wraps a draft such as an email in a writing block, the block is now titled with its subject and shows the recipient beside it, rather than every block reading simply as Writing. [#28280](https://github.com/open-webui/open-webui/pull/28280), [#28198](https://github.com/open-webui/open-webui/issues/28198)
- 🤝 **Files for delegated tasks.** A task handed to a sub-agent can now carry the attachments it needs, so an image or document from your conversation reaches the sub-agent instead of arriving as a file reference it cannot open and may answer about anyway. [#28213](https://github.com/open-webui/open-webui/issues/28213)
- 📟 **Terminal availability and scope.** Administrators can now decide for each managed terminal whether it appears in chats and in automations at all, and whether everyone shares a single workspace or each chat or automation gets its own, with per chat terminals waiting until the conversation has been saved.
- 🔒 **Read-only files in the terminal browser.** Files and folders you are not allowed to change are now labelled read-only, with uploading, editing, renaming, moving, and deleting turned off for them rather than failing at the moment you try.
- 🔐 **Terminals that use your own login.** Managed terminals configured for session authentication now authenticate the terminal connection with your own token, where it previously sent no credentials at all.
- 🎟 **Setting up a tool server that uses OAuth.** Adding one is now easier to get right: the connection dialog can authorize the account from the dialog itself, the check button tests the sign-in details rather than reporting a connection failure that was never going to succeed without them, and it is now labelled for what it does rather than suggesting it verifies the whole connection. [#28552](https://github.com/open-webui/open-webui/issues/28552)
- 🪤 **Control over what embedded pages may do.** Two new interface settings decide whether pages shown inside a chat, such as an artifact or an HTML preview, may run scripts and start downloads. [#28924](https://github.com/open-webui/open-webui/issues/28924)
- 🗄 **Keeping files removed from a knowledge base.** A new "ENABLE_KNOWLEDGE_FILE_RETENTION" setting keeps the stored file and its search data when a file is taken out of a knowledge base, rather than deleting them.
- 🧾 **CSV shape in retrieval.** Turning on "ENABLE_RAG_CSV_SUMMARY" adds a short line naming the row count, data row count, column count, and column names of a CSV file to what the model sees, giving it the shape of the table alongside its contents.
- 🔭 **OpenSERP in the search settings.** OpenSERP can now be picked as the web search engine in the admin panel, with a field for its address, rather than only being configurable through the environment. [#27594](https://github.com/open-webui/open-webui/pull/27594), [#27592](https://github.com/open-webui/open-webui/issues/27592)
- 🪧 **Profile changes from single sign-on.** A name, email address, or picture updated from an identity provider at sign-in now raises an event naming what changed, and the rest of the session uses the updated record rather than a stale copy.
- 📯 **Group changes from single sign-on.** Group memberships added or removed when someone signs in through an identity provider, and groups created automatically along the way, now raise the same events as the equivalent change made by an administrator or over directory sync. [#27657](https://github.com/open-webui/open-webui/pull/27657)
- 🔔 **Sign-in and sign-out events for single sign-on.** Signing in through an identity provider now raises the same login event that signing in with a password does, and signing out says which provider the session came from, so a function can set up or tidy up an account in another system when someone arrives or leaves. [#27619](https://github.com/open-webui/open-webui/pull/27619), [#27613](https://github.com/open-webui/open-webui/issues/27613)
- 🪛 **Naming background worker threads.** A new "THREAD_POOL_THREAD_NAME_PREFIX" setting labels the threads that background work runs in, so they can be told apart when reading a profile or a thread dump.
- 📙 **OpenDocument files in a temporary chat.** A text document, spreadsheet, or presentation from an office suite that uses the OpenDocument format now has its text read out in the browser when attached to a temporary chat, where the model was handed the raw archive and answered that it could not read the file. [#28906](https://github.com/open-webui/open-webui/discussions/28906)
- 🌍 **Pointing Tavily somewhere else.** A new "TAVILY_API_BASE_URL" setting sends Tavily searches and page fetches to a different address, for instances that reach the internet only through a gateway of their own or that use a compatible service. [#28701](https://github.com/open-webui/open-webui/issues/28701)
- 🪟 **Honest OAuth settings.** When single sign-on settings come from the environment rather than being saved in the application, the admin panel now shows them as read-only with a note naming the setting that controls this, instead of accepting edits that were silently discarded on the next restart. [#28276](https://github.com/open-webui/open-webui/pull/28276)
- 📏 **Widening the chat controls pane.** The controls pane can now be dragged as wide as you like, where it stopped at a fixed limit regardless of screen size.
- 📱 **Smoother sidebar on mobile.** The sidebar now follows your finger as you swipe it open or closed, responds to a quick flick, dims the page behind it as it moves, and gives every chat row a menu button you can reach without a hover you cannot perform on a touchscreen.
- 🚪 **Sidebar that stays put.** Opening and closing the sidebar is now a smooth transition that keeps your chat list loaded, instead of rebuilding the list each time.
- 👁️ **Turning off chat previews.** A new setting under Settings and Interface lets you switch off the preview card that appears when you hover a chat in the sidebar, useful for a quieter sidebar, for sharing your screen, or on a slow connection. - ☑️ **Checkboxes beside their labels.** In the model editor and the admin model defaults, each capability, feature, and tool checkbox now sits directly in front of its own label instead of at the far edge of its column, where it could look like it belonged to the next one, and the label itself can be clicked to toggle it. [#27788](https://github.com/open-webui/open-webui/pull/27788), [#27771](https://github.com/open-webui/open-webui/issues/27771)
- ✍️ **Typing cursor while responding.** A blinking cursor now marks where the reply is being written, from the moment you send your message until generation finishes, in place of the previous loading placeholder.
- ✒️ **Underlined text.** Underlined text now appears underlined in a reply instead of showing the markup around it, and underlining is kept when you edit in a rich text box rather than being dropped. [#26904](https://github.com/open-webui/open-webui/issues/26904)

- 📑 **Apache Tika 4 support.** Administrators extracting document text with Tika can now choose which server version they run, from Admin Settings under Documents or through "TIKA_SERVER_VERSION", where only Tika 3 was understood before.
